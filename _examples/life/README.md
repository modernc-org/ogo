# life

Conway's Game of Life on a Propeller 2 — and a differential test against Go.

[`main.ogo`](main.ogo) runs a glider around a 24×12 torus until it meets a
blinker, printing every generation to the serial console. A P2 is not what
anyone reaches for to run Life; the point is what the program *doesn't* have.
There is no `import` at all — no pin, no cog, no intrinsic. It is arrays,
structs, methods and loops, and it is the example to read to see what the
language looks like when the board is out of the way.

## It is the same program in Go

Give the source a package clause and spell `printf` `fmt.Printf`, and it
compiles as Go. Those two substitutions are the whole difference, and the test
suite performs exactly them: `TestExampleMatchesGo` runs the Go twin under
`go run`, runs this one through the compiler and a host C compiler, and
requires the two to print the same bytes. `TestOnBoardExample` makes the same
comparison with a real P2-EDGE standing in for the host.

That is a stronger check than the rest of the corpus gets. Most tests pin
behaviour against what somebody wrote down as expected, which is only as good
as the person who wrote it; this one pins it against the language OctoGo is
modelled on, running the same source. So a divergence is either a bug here or
a place where the two genuinely differ — and both are worth being told about.

## Run

```sh
ogo run _examples/life
```

Press `Ctrl-]` or `Ctrl-Z` to leave the terminal. The program prints nine
generations and stops.

## Build

```sh
ogo build _examples/life
```

## The same program under Go

Nothing in the repo ships the twin — it is generated by the test — but it is
two lines away if you want to watch it run on your machine:

```sh
{ echo 'package main'; echo; echo 'import "fmt"'; echo; \
  sed 's/\bprintf(/fmt.Printf(/g' _examples/life/main.ogo; } > /tmp/life.go
go run /tmp/life.go
```
